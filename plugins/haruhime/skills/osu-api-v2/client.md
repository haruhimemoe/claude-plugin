# @haruhimemoe/osu client: results, budget and errors

- `getBeatmaps(ids, { beforeCall })` returns `{ found, missing, unchecked }`, `getBeatmapsets(ids, { beforeCall, fallbackLimit })` returns `{ sets, unchecked }`, and `getStarRating(id, mods, { beforeCall })` a number (the map in its own ruleset), or null for 404/422. Both lookups ask `/beatmaps` 50 ids at a time, after dropping duplicates.
- **Users (0.4.0 and later):** `getUser(user, { beforeCall, ruleset })` takes an id (number) or a username (string; a name made of digits is still a name) and returns an `OsuUser` (`osuId`, `username`, `avatarUrl`, `countryCode`) or null on 404. `ruleset` only changes the stats osu! sends. `getUsers(ids, { beforeCall })` asks 50 ids per call and returns `{ found, missing, unchecked }` like `getBeatmaps`: `missing` holds bad ids and users osu! didn't send (deleted or restricted).
- **`sets` is keyed by beatmap (difficulty) id, not set id.** Sibling difficulties share one set object, holding the content fields (`OsuBeatmapsetExtended`) that go straight into `@haruhimemoe/compliance`'s `factsFromOsuBeatmapset`.
- **Shared budget:** `beforeCall` runs before each osu! API call; return false to skip it. Back it with one per-app counter (see SKILL.md, "Limits and terms"), stored atomically where every instance sees it (MongoDB, Redis). With no `beforeCall` there is no limit. Token requests and the one 401 retry aren't counted, so one approved call can cost two API calls and up to two token requests: leave headroom.
- **`unchecked` is not `missing`.** `unchecked` holds ids in batches `beforeCall` refused and rows that failed the schema; in `getBeatmapsets` also sets whose `/beatmapsets/{id}` fallback failed (anything but 404) or was skipped once `fallbackLimit` (10, `OSU_BEATMAPSET_FALLBACK_LIMIT` from 0.3.0; the old `BEATMAPSET_FALLBACK_LIMIT` is deprecated) ran out. Retry them later. `missing` means osu! returned no row for the id (or it wasn't a positive safe integer, so it was never sent).
- **A failing `/beatmaps` call throws.** An error status (after the one 401 retry), a timeout, a network error or a bad body on the main call (or the token request) rejects the whole call with `OsuApiError`, dropping batches already fetched. Catch it and retry after `retryAfterMs`. A failed fallback lookup in `getBeatmapsets` never throws; its ids land in `unchecked`.
- `OsuApiError` has `code` (`timeout`, `network`, `bad_response`, `http_error`, `budget`; later versions may add codes), `status` (null without a response), `retryAfterMs` and `cause`. `retryAfterMs` comes from `Retry-After` on 429/503, in delta-seconds or an HTTP date, capped at 60 s; it's null when osu! sent none or sent anything else (in 0.2.0 a malformed value like `1.5` gave 0, "retry now"). Wait 60 s when it's null. A refused `getStarRating` or `getUser` rejects with code `budget`.
- Other errors: a bad `getStarRating` id, a bad `getUser` id, blank name or unknown ruleset, `fallbackLimit`, `timeoutMs` or `baseUrl` throws `RangeError`; bad credentials or `userAgent` throw `TypeError` (from 0.3.0, a `userAgent` that isn't printable ASCII on one line counts as bad). Bad ids given to `getBeatmaps` or `getBeatmapsets` never throw: `getBeatmaps` puts them in `missing`, and `getBeatmapsets` leaves them out of both lists.
- `baseUrl` receives your client secret (token requests go there too). Point it only at osu! or a local test server; it refuses plain http except on `localhost` and `127.0.0.1`.
- TypeScript needs `moduleResolution` `node16`, `nodenext` or `bundler` to resolve `@haruhimemoe/osu/shapes`, `/collections` and `/format`, and the `DOM` lib or `@types/node`. The root entry re-exports `/collections`, whose types need TypeScript 5.7 or later: importing even just `createOsuClient` needs 5.7, or `skipLibCheck`.
- The [README](https://github.com/haruhimemoe/osu#readme) has the full API and a MongoDB budget example.
